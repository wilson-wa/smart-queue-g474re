# 智慧排隊叫號機（NUCLEO-G474RE 期中專題）

客人抽號、店員用電腦叫號、燈號看狀態；10 秒沒報到自動過號，緊急時可一鍵暫停。

## 1. 情境故事
午餐時間的小吃店，客人擠在櫃台前，店員一邊做餐一邊要一直喊號，客人也不知道還要等多久。這台叫號機讓客人抽號、店員在電腦上打指令叫號，用燈號顯示排隊人數和叫號狀態，客人 10 秒沒到就自動過號叫下一位。

## 2. 替身對照
| 故事裡的模組 | 板上替身 | 背後技術 |
|---|---|---|
| 取號機按鈕 | 外接按鈕 PB5（D4）；終端機 `take` 指令代打 | EXTI＋軟體去彈跳 |
| 緊急停止開關 | 藍色按鈕 B1（PC13） | EXTI，優先權最高 |
| 店員電腦與叫號螢幕 | 終端機 115200 8N1 | USART2 中斷＋環形緩衝 |
| 排隊人數燈 | 黃色 LED（PC7） | TIM3 CH2 PWM |
| 叫號狀態燈 | 綠色 LED（PC8） | TIM3 CH3 PWM |
| 緊急指示 | 黃綠燈熄滅＋終端機訊息；PC6 有輸出，外接紅燈未接 | GPIO 輸出 |

## 3. 功能與驗收
| 功能 | 驗收方式 | 預期結果 | 實測 |
|---|---|---|---|
| 開機訊息 | 按 RESET | 印 `QUEUE READY` | 通過 |
| 抽號 | 打 `take`（按鈕替身） | 依序印 001、002… | 通過 |
| 客滿 | 隊伍 16 人後再抽 | 印「客滿」 | 程式完成 |
| 查看隊伍 | 打 `list` | 印「排隊中：001 002」 | 通過 |
| 叫號 | 打 `next` | 印「請 001 到櫃台」 | 通過 |
| 報到 | 叫號後打 `ok` | 印「001 報到」，綠燈恆亮 | 程式完成 |
| 過號 | 叫號後 10 秒不報到 | 印「001 過號」並自動叫下一位 | 程式完成 |
| 緊急暫停 | 按 B1 | 印「緊急暫停」，黃綠燈熄滅，`next` 無效；再按恢復 | 通過（印出緊急暫停） |
| 排隊人數燈 | 抽號 | 黃燈隨人數變亮，16 人全亮 | 程式完成 |
| 叫號狀態燈 | `next`、`ok` | 綠燈等待時呼吸、報到後恆亮 | 程式完成 |

## 4. 用到的技術（第 3～7 週）
| 技術 | 用到 | 用在哪 |
|---|---|---|
| GPIO 輸出 | ☑ | PC6 緊急輸出（外接紅燈未接） |
| GPIO 輸入 | ☑ | 抽號按鈕 PB5，內部上拉 |
| 複用功能 AF | ☑ | USART2 PA2／PA3 選 AF7；PC7／PC8 選 AF2 接 TIM3 |
| 時脈 PLL 170 MHz | ☑ | HSI 16 MHz ÷ 4 × 85 ÷ 2 |
| 外部中斷 EXTI | ☑ | 抽號 PB5（EXTI5，下降緣）、緊急 PC13（EXTI13） |
| NVIC 優先權 | ☑ | EXTI15_10＝0、SysTick＝1、USART2＝2、TIM6＝3、EXTI9_5＝4 |
| 軟體去彈跳 | ☑ | 抽號與 B1，穩定 50 ms 才算一次 |
| UART 傳送 | ☑ | 印號碼與狀態 |
| UART 接收＋環形緩衝 | ☑ | 中斷收字放進 64 格環形緩衝，收到 Enter 解析指令 |
| 環形緩衝（排隊） | ☑ | 16 格現場隊伍，head／tail／count |
| PWM | ☑ | 黃燈 CCR＝人數×1000÷16；綠燈呼吸 |
| Timer 定時中斷 | ☐ | TIM6 已設 PSC 169、ARR 999（1 ms），過號改用 HAL_GetTick |
| 輸入捕捉 | ☐ | TIM2 已設 PWM Input、PSC 169，程式未完成 |

## 5. 腳位表
| 腳位 | 用途 |
|---|---|
| PB5（D4） | 抽號按鈕（EXTI5，下降緣，內部上拉） |
| PC13 | 板載 B1，緊急暫停（EXTI13） |
| PA2／PA3 | USART2 TX／RX（ST-LINK 虛擬 COM 埠） |
| PC7（D9） | 黃燈，TIM3 CH2 PWM |
| PC8 | 綠燈，TIM3 CH3 PWM |
| PC6 | 緊急輸出（外接紅燈未接） |

LED 接法：腳位 → 電阻 → LED 長腳，LED 短腳 → GND。

## 6. 建置與執行
1. STM32CubeIDE 開啟專案 → 編譯 → 燒錄（Run）
2. 終端機（PuTTY）選 STLink Virtual COM Port，115200 8N1，編碼 UTF-8，Local echo 關閉
3. 按 RESET，出現 `QUEUE READY` 後**先按一次 Enter**，再輸入指令

| 指令 | 功能 |
|---|---|
| `take` | 抽一個號碼（按鈕替身） |
| `next` | 叫下一位（等待報到中或緊急暫停時無效） |
| `ok` | 目前叫到的號碼報到 |
| `list` | 列出排隊中的號碼 |

## 7. 程式結構
全部在 `Core/Src/main.c` 的 USER CODE 區塊。

- **中斷只做登記**：`HAL_GPIO_EXTI_Callback` 只設旗標並記時間；`HAL_UART_RxCpltCallback` 只把字放進環形緩衝
- **主迴圈做事**：按鈕去彈跳 → 取 UART 字元組成指令 → B1 暫停切換 → 10 秒過號檢查 → 更新燈號
- 主要函式：`Take_Ticket()` 抽號入列、`Call_Next()` 叫號出列、`Command_Handle()` 解析指令、`UART_Print()` 輸出字串

## 8. 實作照片
終端機實測輸出（2026-11-03 上板）：
```
QUEUE READY
> take
001
> take
002
> list
排隊中：001 002
> next
請 001 到櫃台
（按 B1）
緊急暫停
```

我的查核：

## 10. 已知限制
- 實體抽號按鈕：PC9 讀不到改用 PB5；偵錯顯示 EXTI 次數會增加但按住時讀值仍為 1，判斷為接線或接地問題，Demo 以 `take` 指令代替
- 外接紅燈 PC6 未接，緊急狀態以黃綠燈熄滅＋終端機訊息表示
- 開機後第一個指令可能被雜訊吃掉，需先按一次 Enter
- 預約、公平點數、預約遲到降級、輸入捕捉自我健檢尚未完成
- 隊伍存在 RAM，斷電後清空；隊伍最多 16 人
- 指令區分大小寫，不支援退格修改
